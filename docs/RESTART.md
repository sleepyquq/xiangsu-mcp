# 恢复维护：先解决连接，再接入官方能力

2026-10-28 恢复维护。0.3.0 完成像塑 9.7.2 适配，吸收此前的兼容工作并接入官方 MCP 能力。[中文 README](../README.md) 为主版，[English README](../README.en.md) 为独立英文版，已列明版本对应与优先使用官方 MCP 的建议；版本下载见 [Releases](https://github.com/sleepyquq/xiangsu-mcp/releases)。

## 社区提出的是连接差异

[Issue #5 的新回复](https://github.com/sleepyquq/xiangsu-mcp/issues/5#issuecomment-6419797371) 反馈：官方 MCP 无法连接 GPT，而本项目可以。维护者已回复将做新版适配。

反馈尚未说明 GPT 的具体宿主、操作系统、官方连接配置和报错，因此当前可确认的是存在客户端连接兼容需求，不能推断官方服务整体不可用，也不能把工具数量当作体验优劣。

## 更新顺序

1. 使用像塑内部原生更新器更新本机编辑器，再确定新版接口基线。
2. 对照官方 MCP 的工具清单、参数和配套 Skill，区分已有等价能力、真正新增能力和仅用于官方宿主的管理工具。
3. 保留本项目的 stdio 入口、旧工具契约和独立插件通道；新增官方能力不让旧调用强制依赖官方 Gateway。
4. 官方新增能力优先通过公开 MCP 协议接入，不把官方程序、模型、运行库或整套私有实现复制进仓库。

## 接入方向

已实现“稳定客户端入口 + 两条明确执行路径”：现有功能继续使用原插件桥接；官方 38 个原名工具通过本地 MCP 客户端适配器访问官方服务，保留原参数和完整 MCP 结果。官方路径不可用时给出可操作的连接错误，不静默降级，也不阻断原插件功能。

新路径需要保留官方参数含义、工程实例绑定、图像/资源返回和错误状态；场景写入超时不能自动重放。云端生成仍使用像塑正常登录及权限流程，不自行读取账号令牌。

原有运行状态读取、音频检测输入模拟和批次预检继续保留。新版实现的验证围绕实际改动，不重启与本次目标无关的防御性验收。

## 9.7.2 官方能力对照

通过安装配置中的地址读取官方 MCP `initialize` 和 `tools/list`，共 38 个工具，与 9.7.1 相比没有新增工具名。安装包/Skill 为 1.2.3，MCP 服务握手版本为 1.0.0；这两个版本号都不是编辑器版本。

下表覆盖这 38 个入口。对照对象是现有桥接代码与已公开 0.2.2 的能力，不把“入口存在”算作新功能已接入。

| 能力组 | 官方入口 | 与现有桥接的差异及接入方式 |
| --- | --- | --- |
| 服务与工程连接 | `health`、`list_instances`、`get_project_context`、`report_install` | 已有自制会话发现；新增官方实例发现及上下文。安装上报属于安装流程，不作每次连接的固定步骤。 |
| 场景与资源编辑 | `get_scene`、`inspect`、`describe_project`、`list_resources`、`edit_by_dsl` | 已有大量等价基础能力；保留旧调用，同时提供新版 DSL 和摘要查询，不把旧接口参数强行改成官方格式。 |
| 可视化检查与知识查询 | `get_scene_view`、`read_visual_scripting_graph`、`preview_asset`、`validate_omtl`、`query_knowledge` | 补场景截图标注/对象边界、可视化脚本图读取、资源预览、独立材质语法校验及官方知识查询。已有场景截图、材质编译等相近能力不重复算增量。 |
| 预览与输入管理 | `set_preview_video`、`list_preview_videos`、`get_current_preview_video`、`capture_preview`、`interact_by_dsl` | 截图/交互/录像已有；补统一的预览输入枚举、当前输入读回与切换。保留原有状态查询和音频输入模拟。 |
| 工程与脚本管理 | `project_status`、`save_plan`、`update_handoff_context`、`save_project`、`get_script_logs`、`run_otsc_check` | 编译、日志已有；主要补原生保存和保存状态、官方方案/续接上下文。支持按需写入上下文，不自动复制用户对话。 |
| 图片和音频生成 | `generate_image`、`generate_audio`、`generate_assets_batch` | 真正缺口：旧 7 个云端占位入口尚未实现。接入官方单项/批量生成及导入，不继续仿造私有云端请求。 |
| AI 工作流 | `get_workflow_context`、`get_workflow_capabilities`、`upload_workflow_image`、`apply_workflow_patch`、`generate_workflow`、`get_workflow_generation_status`、`download_workflow_node_asset` | 真正缺口：图查询、模型能力、原图上传、节点修改/连线、整图生成、状态查询和结果下载。保留官方 revision/request_id 语义，未知提交结果不重提。 |
| H5 脚本动画 | `get_h5_render_config`、`import_h5_render_bundle`、`get_h5_import_status` | 真正缺口：渲染参数、打包产物导入和状态。需连同官方制作/打包 Skill 的实际产物流程接入，不能只注册 3 个工具就声称完整支持。 |

9.7.2 原生更新说明还列出 Seedance 2.5、最长 30 秒单段视频/2 分钟工作流组合输出及两项修复。但当前 MCP 没有单独的 `generate_video`，工作流 Patch 仅明确开放图片输入/图片生成节点及通用连线等操作，不能把编辑器 UI 新增能力自动承诺为 MCP 已支持。
